# 联运争议材料的证据反驳与可读摘录

联运材料交换登记采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/材料.json` | `id`、`party`、`language`、`sourceLink`、`access`、`text` |
| `资料/运单.json` | `id`、`lot`、`segment`、`from`、`to` |
| `资料/陈述.json` | `id`、`submittedBy`、`requestedFact`、`text` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 整理工具

在 `readMaterials` 之上，三个模块把双方陈述整理为有出处的争点、反驳和可交换摘录，支持后续材料交换；正式判断仍由调解组作出。

- `analysis.js`：辨认陈述人与转述人（转发/引用构成转述链，根源才是独立来源，同源转述不重复计入交叉印证）；按子句辨认肯定、否定、条件与不确定；区段定位以运单表解析货批号，"最后一站 / final station"一类说法保持不可定位；无法定位到具体区段的新陈述标记为请提交者补充定位，其他依据继续支持争点。
- `excerpts.js`：生成可交换摘录，隐去联系人与商业条款；限制词（仅、未、如果……）不能保留时宁可不提供，并在交换单写明仍缺什么事实。已送出的摘录可审计：只复用原句几个字的引用也能找回出处子句，并指出丢失的限制词。
- `ledger.js`：按场次登记摘录、回应与来源争议。共享摘录可直接双边查看，提供方确认的材料先挂起，仅主管材料不进入双边交换；回应留在原交换场次；来源争议会重估支撑/反驳是否成立，并回查已送出摘录是否造成误解，误导性摘录引来回应的，下一轮按完整语义重新发问。每方当时见到的文字、所依据的来源和仍需核对出处的争点均可按场次查询（主管见全部，各方只见获准范围）。

```sh
npm run exchange   # 演示一轮交换、审计、来源争议与下一轮安排
```
